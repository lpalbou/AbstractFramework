Install AbstractFramework

One download or one line. No admin password, no system Python to prepare. At the end, AbstractFramework opens in your web browser, already signed in, and a first-run guide helps you pick an engine and a model that fits your machine.

Pick the line for your computer

Every way below runs the same installer script, so the result is the same. Running it again repairs or upgrades the install in place.

Without Terminal: the Mac package.

  • Download AbstractFramework-Installer.pkg (attached to every GitHub release) and double-click it.
  • The package is not signed with an Apple Developer ID, so macOS blocks it the first time. Close the warning, open System Settings > Privacy & Security, click Open Anyway next to the installer's name and confirm. You do this once per download.
  • Click Continue, then Install; it installs for you only, so it does not ask for your password. A Terminal window then shows each step and asks one question: Start AbstractFramework automatically when you log in? Press Return for yes.
  • It also leaves Install AbstractFramework.command (repair) and Uninstall AbstractFramework.command in ~/Library/Application Support/AbstractFramework/Installer.

With Terminal: one line. Paste it and press Return; it runs the same installer.

curl -LsSf https://raw.githubusercontent.com/lpalbou/AbstractFramework/main/scripts/install.sh | sh
  • macOS 13 or later (the Apple Silicon engines need macOS 14), about 5 GB of free disk before models, and an internet connection.
  • With no answer to the start-at-login question within 25 seconds, it leaves start at login off. Pass options after sh -s --, for example … | sh -s -- --with-ollama. See Options.
curl -LsSf https://raw.githubusercontent.com/lpalbou/AbstractFramework/main/scripts/install.sh | sh
  • Paste it in a terminal and press Return. It asks whether to start at login (a systemd --user service); Enter = yes, no answer within 25 seconds leaves it off. Your data lives in ~/.local/share/abstractgateway.
  • glibc distributions on x86_64 or aarch64; about 5 GB of free disk before models. The gpu profile is picked when nvidia-smi or rocminfo works.
  • Headless or over SSH: the same line works. It does not open a browser on the server; it offers the terminal console at the end instead, and one SSH tunnel reaches the web console and every app. See Headless or remote server.
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/lpalbou/AbstractFramework/main/scripts/install.ps1 | iex"
  • Windows 10 22H2 or later, or Windows 11. Open PowerShell, paste the line and press Enter.
  • It installs under your user account (no administrator rights), asks whether to start AbstractFramework at sign-in (Enter = yes) and opens it in your browser.
  • -NoService leaves start at sign-in off and asks nothing. The terminal console and abstractcode are built into %USERPROFILE%\.local\bin when Rust is already installed.
# the same install, step by step
curl -LsSf https://astral.sh/uv/install.sh | sh
uv python install 3.12
uv tool install --python 3.12 "abstractgateway[tray]==0.7.1"   # [apple,tray] or [gpu,tray] for local engines
uv tool update-shell                                         # puts ~/.local/bin on PATH; open a new terminal
abstractgateway service install --port 8080                  # or: abstractgateway serve
abstractgateway-config claim-url --base-url http://127.0.0.1:8080
  • The last command prints a one-time sign-in link for the console (valid 10 minutes, this machine only).
  • To avoid compiling anything, add the --with and --overrides arguments that install.sh --print shows.

Checks this machine

OS, CPU, disk, a free port, internet access, NVIDIA or ROCm. It picks a profile: apple on Apple Silicon (macOS 14+), gpu with a working NVIDIA or ROCm GPU, light otherwise.

Installs in your account

uv and a private Python 3.12, then the gateway as an isolated tool, with local voice (Supertonic text-to-speech and Whisper speech-to-text, on CPU). Prebuilt wheels only: no compiler needed.

Puts the commands on PATH

Builds the terminal console and AbstractCode’s terminal client with cargo (Rust from rustup when missing), and exposes the library commands, all in ~/.local/bin next to abstractgateway. A failed build never fails the install. Commands you get

Opens the console

Starts the gateway on 127.0.0.1:8080, writes ~/.abstractframework/gateway.json so every client finds it, and opens the web console through a one-time sign-in link.

Afterwards, AbstractFramework is at http://127.0.0.1:8080/console (bookmark it). On a Mac its menu-bar icon opens it and shows its status. The browser apps open from the console's Apps page at http://127.0.0.1:8080/apps/<app>/. Next: what the console does, or pick a starting point.
Commands you get

Every command in one folder

Everything lands in ~/.local/bin (Windows: %USERPROFILE%\.local\bin), which the installer adds to your shell profile: open a new terminal for it to be on PATH. The summary lists them under Commands.

CommandWhat it doesOpt out
abstractgatewayThe gateway: serve, service (start at login), network, models, engines, apps—
abstractgateway-configThe gateway’s admin command: status, claim-url (a new sign-in link), defaults and settings—
abstractgateway-consoleThe terminal console--no-console
abstractcodeAbstractCode’s terminal client (sign it in once, below)--no-code-cli
abstractcore, abstractcore-chat, abstractcore-endpointAbstractCore’s configuration and operations (--config, models, engines, serve), a terminal chat, a single-model /v1 server--no-core-cli
summarizer, extractor, judge, intent, deepsearchAbstractCore’s apps (also as abstractcore-<app>): summarise a document, extract a knowledge graph, LLM-as-a-judge, intent analysis, a sourced web research report
abstractvoice, abstractvoice-prefetch, abstractvision, abstractmusicVoice, images and video, and music in the terminal, from the gateway’s own environment so they match the versions it runs

A package’s commands come all together or not at all: when another program already has one of its names, the installer leaves that package out with a warning naming the file, and installs the rest.

Sign the terminal app in

abstractcode login --token <admin token>   # once; the summary prints it with your token
abstractcode

# or, on the gateway's computer, without handling a token:
abstractgateway apps tui-command code

The installer never saves the token for you. tui-command prints a one-time line, valid 2 minutes, that opens abstractcode signed in. Started without a sign-in, abstractcode says so and prints both lines.

One folder for the terminal apps

The console’s Apps page installs and updates abstractcode in the same folder as the installer, so it runs by name whichever of the two installed it. A re-run of the installer keeps an abstractcode newer than its pin, and the uninstaller removes it with the console.

Install profiles

The installer picks the profile for you; --profile overrides it. The framework's features are the same in every profile; the profile decides which local inference engines are installed.

Remote and endpoint engines only: OpenAI, Anthropic, OpenRouter, Portkey, and servers such as LM Studio, Ollama, vLLM or any OpenAI-compatible endpoint. Works everywhere.

Remote & headless

A Linux server over SSH works like a Mac

Install with the same one-liner over SSH. You configure the gateway from the terminal console on the server, and one SSH tunnel carries the web console, the API and every browser app to your own computer.

Install over SSH

ssh -t <server>
curl -LsSf https://raw.githubusercontent.com/lpalbou/AbstractFramework/main/scripts/install.sh | sh

It asks the start-at-login question in your SSH terminal, installs local voice like every install, and at the end offers to open the terminal console, signed in ("Press Enter within 25 s"). No answer skips it, so a scripted install never hangs. Over SSH it does not open a browser on the server.

Configure from the terminal console

abstractgateway-console --gateway-url http://127.0.0.1:8080 --token <admin token>

The installer's summary prints this command with your port and token filled in; the admin token is also in ~/.local/share/abstractgateway/auth/bootstrap-admin-token. The console runs the same setup guide as the web console. Press N for Network, A for Apps, F3 for the gateway host (restart, update, start at login).

Reach the web console and apps through one tunnel

ssh -L 8080:127.0.0.1:8080 <server>
# on the server, print a one-time sign-in link for your browser:
abstractgateway-config claim-url --base-url http://127.0.0.1:8080

Open the link in your browser, then open the apps from the console's Apps page: each one is served at http://127.0.0.1:8080/apps/<app>/ (observer, code, flow, continuum, entity).

Network & start at login

This computer only, until you choose otherwise

The gateway listens on 127.0.0.1:8080 by default. Change who can reach it in the web console's Network tab, the terminal console's Network screen (N), the menu-bar icon, or the command line.

Network

abstractgateway network status
abstractgateway network set lan          # devices on your local network
abstractgateway network set localhost --port 8080
abstractgateway network set internet --acknowledge-internet
abstractgateway network restart --token <admin token>
abstractgateway network addresses

A new mode applies at the next start. Internet mode leaves TLS and port forwarding to you: read Gateway security first.

Start at login

abstractgateway service enable     # start at the next login
abstractgateway service disable
abstractgateway service install --port 8080
abstractgateway service status
abstractgateway service uninstall  # data is kept

Or flip the Start at login switch in either console. It is a LaunchAgent on macOS, a systemd --user unit on Linux and a per-user Run entry on Windows.

If something goes wrong

Run it again

The installer stops at the first problem, says what happened in plain words and what to do. After you fix the cause, run it again: it continues where it stopped.

What you seeWhat to do
no internet connection: the installer could not reach pypi.orgConnect to the internet and run it again. Nothing was changed.
this Terminal runs in Intel (Rosetta) mode on an Apple Silicon MacUntick Open using Rosetta in Terminal's Get Info window, then run it again.
the Apple Silicon engines (MLX) need macOS 14 or laterYou get the light version. Update macOS and run the installer again to add the local engines.
The browser page asks for a tokenThe one-time link lasts 10 minutes. Run the installer again for a fresh link, or run abstractgateway claim --open.
Anything elseRun it again. If it stops at the same step, report it with the log file named at the end of the message.

Check an install

uvx abstractframework doctor

Checks Python, uv, Node, disk, the gateway and whether Ollama and LM Studio answer. It only reads.

Upgrade

# re-run the same line you installed with
curl -LsSf https://raw.githubusercontent.com/lpalbou/AbstractFramework/main/scripts/install.sh | sh

The line always runs the installer of the latest release: it installs the gateway version that release pins, rebuilds the terminal apps when newer ones are pinned, and keeps your profile, port, start-at-login choice, network setting, data, models and apps. On Windows, run the PowerShell line again; on a Mac without Terminal, install the latest .pkg again. The gateway can also update itself from the Gateway card in the console (terminal console: F3) and from the menu-bar icon.

Remove

curl -LsSf https://raw.githubusercontent.com/lpalbou/AbstractFramework/main/scripts/uninstall.sh | sh

It asks before deleting anything, keeps your data unless you say yes, and keeps model weights and shared caches. Windows: install.ps1 -Uninstall [-Purge].

Developers & servers

Python profiles and containers

Want every framework library in your own Python environment, or a container on a server? Use the meta-package or the gateway image. Python 3.10 to 3.13.

python3 -m venv .venv && source .venv/bin/activate
python -m pip install abstractframework
abstractframework doctor
abstractgateway serve     # prints a one-time console link
  • Remote-first: cloud APIs and endpoint servers (LM Studio, Ollama, vLLM, llama.cpp, OpenAI-compatible). Multimodal input and output, tools, durable runs and workflows all work.
pip install "abstractframework[apple]"
  • macOS 14 or later on Apple Silicon. Local MLX and Metal engines next to the endpoint providers. A plain pip install of this profile builds a few compiled extras from source and needs a C/C++ compiler; the one-line installer does not.
pip install "abstractframework[gpu]"
  • Linux (and Windows where the engines publish wheels) with NVIDIA CUDA or AMD ROCm drivers. Voice cloning with F5-TTS needs Python 3.11+.
docker run \
  -p 8080:8080 \
  -v "$PWD/runtime:/data" \
  -e ABSTRACTGATEWAY_DATA_DIR=/data \
  -e ABSTRACTGATEWAY_USER_AUTH=1 \
  ghcr.io/lpalbou/abstractgateway:0.7.1
  • The light container: every framework capability through remote or endpoint inference. On first start it creates default/admin and writes the login token to runtime/auth/bootstrap-admin-token.
  • ghcr.io/lpalbou/abstractgateway:gpu-latest is an experimental local GPU image for NVIDIA hosts. The AbstractCore OpenAI-compatible server is ghcr.io/lpalbou/abstractcore-server:2.18.0.
