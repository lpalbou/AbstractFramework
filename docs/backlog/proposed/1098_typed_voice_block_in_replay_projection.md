# 1098 — Typed voice block in the replay projection

> Package: AbstractRuntime, AbstractGateway, AbstractAssistant (watch, phone, web), AbstractUIC (panel-chat), AbstractCode
> Type: task
> Created: 2026-11-02
> Priority: normal
> Labels: voice, history-bundle, adr-0047, deferred
> Split: 2026-11-03 (backlog hygiene). This item keeps the typed `voice` block. Which projection clients render a
> conversation from (replay view or history bundle) is [1114](1114_one_conversation_projection_replay_view_or_history_bundle.md).

## Summary

Make voice transport a typed fact on each conversation turn instead of an erased one. Today
(ADR 0047, 2026-11-02) the runtime drops a spoken question's recording and an answer's read-aloud audio from a turn's
`attachments`/`artifacts`; the gateway listing hides them by default; the shared Swift client re-applies
the rule. Nothing left in the projection says the question was spoken or the answer read aloud, so no
view can show a mic glyph or replay what was heard. Operator principle: every client receives the same
data and only interprets it differently. The scope below was written against the history bundle's
session turns; which projection carries the block is decided in
[1114](1114_one_conversation_projection_replay_view_or_history_bundle.md).

## Why

Operator, 2026-11-02: "clients must all receive the same data but can interpret it differently to
create different views" and "the voice that I sent when speaking should never appear as an attachment,
same thing for the voice generated by the AI". Investigation reports (read first):
`untracked/voice-stall/abstraction-server.md`, `untracked/voice-stall/abstraction-clients.md`.
Deferred by the operator on 2026-11-02 ("we can't afford to do it now").

## Scope

### In scope

- Runtime: additive per-turn `voice` block in `_best_effort_session_turns`
  (`abstractruntime/history_bundle.py`), schema `abstractruntime.session_turn_voice.v1`:
  `dictation` (artifact, owner run, duration, transcription request, transcript artifact, `available`)
  or null, and `playback[]` (one entry per `wf_abstractcore_run_facade_tts_stream` child: child run,
  artifact, created_at, status, provider, model, voice, duration, `available`). Playback artifacts are
  owned by the PARENT run; missing artifacts are `available: false`, never dropped. `attachments` and
  `artifacts` keep excluding transport.
- Runtime: one predicate module `abstractruntime/voice_transport.py` (predicates incl. the legacy
  stream-provenance clause, `dictation_tags`); `abstractgateway/voice_artifacts.py` becomes a re-export;
  gateway runtime floor bump; the parity test collapses to identity.
- Gateway: `runs/start` accepts and VALIDATES `input_data.context.voice.dictation`
  (`{"$artifact", "run_id", "request_id", "transcript": {"$artifact"}}`: artifact exists, belongs to the
  session, is tagged transport, is audio; else 422 `voice_dictation_invalid`); never filled server-side.
  The transcribe route tags its transcript artifact as transport (today it is an untagged `derived_text`
  that only a phone-side inference hides).
- Clients: watch and phone pass the dictation reference at run start (`transcribe` keeps the artifact
  ref); every client reads the `voice` block from the projection chosen in 1114. UI: hide by default,
  mic glyph on a spoken question, replay through the existing speaker control. Moving every client onto
  one projection (the watch's media source, panel-chat's per-turn run fan-out, the Code TUI and desktop
  lanes) is 1114's scope.
- Retire the client guards (`SessionTurn.isVoiceTransport`, `sessionHistoryByTurns`, the watch listing
  fallback) in the same release, one release after the apps' CHANGELOG names the gateway floor.
- ADR 0047: add "the projection types voice transport, it does not erase it" and the provenance clause.

### Out of scope

- A voice history surface (listening to one's own recordings): a separate decision.
- Any filename-based rule (`tts-` prefixes): forbidden by ADR 0047.
- Time-window linking of a recording to a turn: rejected (silent mislinks).

## Current code reality (2026-11-02, uncommitted in the working trees)

- Runtime `history_bundle.py` `is_voice_transport` + filter in session turns; `conversation_search.py`
  uses it. Gateway `voice_artifacts.py` (`is_voice_dictation`, `is_voice_transport`, `dictation_tags`),
  upload stamping, listing default filter (`include_voice` keeps the archive view).
- Shared Swift `SessionTurn` decodes `attachments`/`artifacts` (generated media only) and applies
  `isVoiceTransport`; the phone opens a conversation with one `sessionHistory` read; the watch reads
  media from `GET /sessions/{id}/artifacts`.
- Dictation provenance is absent: the turn's input context holds only `messages` and `task`.
- Red targets already in place: `abstractruntime/tests/test_voice_projection_contract.py`
  (3 strict xfails + 4 characterization tests), `SessionTurnProjectionTests.swift` (1 disabled test).
