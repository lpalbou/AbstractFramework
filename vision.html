AbstractVision

Generative images and video behind one Python API: text-to-image, image editing, upscaling, text-to-video and image-to-video. The base install calls OpenAI or any OpenAI-compatible image server; Diffusers, stable-diffusion.cpp and MLX-Gen run models on your own machine through explicit extras. Installed next to AbstractCore, it becomes llm.vision.

GitHub PyPI Documentation llms.txt llms-full.txt 
# OpenAI-compatible HTTP backend
pip install abstractvision

# Local MLX-Gen models (Apple Silicon)
pip install "abstractvision[models,mlx-gen]"

# Local Diffusers + stable-diffusion.cpp
pip install "abstractvision[local]"
Overview

One API, the backend you choose

VisionManager is a thin layer over a backend. You keep the same calls when you move from a hosted endpoint to a model on your laptop or GPU server.

Light base install

pip install abstractvision brings the API, the CLI, the capability registry, the AbstractCore plugin and a stdlib-only OpenAI-compatible HTTP backend. Torch, Diffusers and MLX come only with the extras you pick.

Capability registry

A packaged registry says which task each model supports, with its defaults. The CLI, the playground and the AbstractCore plugin use it to shape requests, and abstractvision show-model prints the contract of one model before you run it.

Artifact refs

Give the manager a store and each result comes back as a small JSON ref ({"$artifact": ...}) instead of raw bytes, so it can travel between processes. RuntimeArtifactStoreAdapter writes into an AbstractRuntime artifact store.

Included in the one-line installer. The AbstractFramework installer installs AbstractVision with the gateway: the OpenAI-compatible backend on every profile, plus Diffusers and stable-diffusion.cpp with the apple and gpu profiles, and MLX-Gen with the apple profile. The abstractvision command is on your PATH (~/.local/bin). To upgrade, re-run the same install line (on a Mac without Terminal, install the latest .pkg again), or use Update on the Gateway card of the console (terminal console: F3) or in the menu-bar icon: see Upgrade.

Backends

Four backends, one set of tasks

The tasks are text_to_image, image_to_image, image_upscale, text_to_video and image_to_video. Which ones you get depends on the backend.

BackendInstallTasksNotes
OpenAI-compatible HTTP (default)baseText to image, image to image; video when you configure the endpointsWorks with OpenAI (default model gpt-image-1) or any compatible /v1 server, local or remote.
Diffusers[diffusers]Text to image, image to imageHugging Face pipelines on CUDA, Apple MPS or CPU. On Windows/Linux, install a CUDA build of PyTorch first to use an NVIDIA GPU. Local Diffusers text-to-video is experimental and disabled.
stable-diffusion.cpp (GGUF)[sdcpp] or automaticText to image, image to imageInstalls sd-cli on first use (or uses the Python bindings). Curated FLUX and Qwen GGUF bundles find their VAE and text encoder automatically.
MLX-Gen[mlx-gen]All fiveValidated on Apple Silicon first; the extra also installs on Linux where upstream mlx-gen / mlx support exists.

Platform profiles: [apple] / [all-apple] (Diffusers on MPS, stable-diffusion.cpp, MLX-Gen) and [gpu] / [all-gpu] (Diffusers, stable-diffusion.cpp in all-gpu, and MLX-Gen when the platform markers match). multi_view_image is in the API, but no backend implements it yet.

MLX-Gen

Local images and video on Apple Silicon

MLX-Gen is a local image and video generation runtime for Apple Silicon and MLX, started as a fork of mflux. AbstractVision 0.3.30 uses mlx-gen 0.38.x. Prepared q4 and q8 models are published in the AbstractFramework/mlx-gen collection on Hugging Face.

Text to image

FLUX.2 (klein and base), Qwen Image, Z-Image, ERNIE Image Turbo, FIBO and the Bonsai ternary model. Pick q4 for memory, q8 for quality, by choosing the exact model id.

Image to image

FLUX.2 klein/base, Qwen Image Edit, ERNIE Image Turbo, FIBO and FIBO Edit, with multi-reference edits on FLUX.2 and Qwen Image Edit, masked edits on Qwen 2511 and structured control on base Qwen Image.

Video

Wan 2.2 TI2V-5B, plus the Wan 2.2 A14B text-to-video and first-frame image-to-video packages. Run TI2V-5B at 832×480 or above; A14B sizes must be multiples of 16.

Upscaling

SeedVR2 3B and 7B single-image upscaling (abstractvision upscale). Start with seedvr2-3b-8bit, move to 7B when memory allows.

LoRA

One lora_adapters request shape across images and video; each route reports whether it supports LoRA.

More in mlxgen

The standalone mlxgen command adds video-to-video, Wan2.1-VACE, MiniMax-H3 video with sound, Bernini-R and SwiftVR restoration. See the MLX-Gen documentation.

Plan memory for video. Wan q8 packages save disk and download, not memory: they load at BF16. The TI2V-5B q8 package is 16.9 GiB on disk (BF16: 21.2 GiB). Memory needed to generate, including overhead: TI2V-5B about 63.5 GiB at its default 1280×704 and about 34.3 GiB at 832×480 (121 frames; measured peak 32.7 GiB); T2V-A14B about 75.2 GiB at its default 1280×720, 49.7 GiB at 832×480 and 43.9 GiB at 640×352 (81 frames). These come from runs on an M5 Max with 128 GB; the frame size sets the need, not the frame count or the number of steps. The console’s recommendations table says which size fits your Mac.

Getting started

First image, first clip

Requires Python 3.9 or later (MLX-Gen: 3.10 or later). Downloads are explicit: generation reads from the Hugging Face cache unless you enable runtime downloads.

Command line (MLX-Gen)

# Already on PATH with the AbstractFramework installer (apple profile); otherwise:
pip install "abstractvision[models,mlx-gen]"
abstractvision catalog --provider mlx-gen
abstractvision download AbstractFramework/flux.2-klein-4b-4bit --provider mlx-gen

# Text to image
abstractvision t2i --provider mlx-gen --model AbstractFramework/flux.2-klein-4b-4bit \
  "a product photo of a matte black espresso machine" --steps 4 --guidance-scale 1.0

# Upscale 2x with SeedVR2
abstractvision download AbstractFramework/seedvr2-3b-8bit --provider mlx-gen
abstractvision upscale --provider mlx-gen --model AbstractFramework/seedvr2-3b-8bit \
  --image ./input.png --resolution 2x --softness 0.25 --open

# Text to video with Wan 2.2 A14B
abstractvision download AbstractFramework/wan2.2-t2v-a14b-diffusers-8bit --provider mlx-gen
abstractvision t2v --provider mlx-gen --model AbstractFramework/wan2.2-t2v-a14b-diffusers-8bit \
  "a red fox walking through a snowy forest, cinematic" --width 480 --height 240 \
  --frames 41 --fps 10 --steps 20 --guidance-scale 4.0 --guidance-2 3.0

# Interactive CLI and the local web playground
abstractvision cli
abstractvision playground --port 8091
from abstractvision import LocalAssetStore, VisionManager
from abstractvision.backends import OpenAICompatibleBackendConfig, OpenAICompatibleVisionBackend

backend = OpenAICompatibleVisionBackend(
    config=OpenAICompatibleBackendConfig(base_url="http://localhost:1234/v1")
)
vm = VisionManager(backend=backend, store=LocalAssetStore())

ref = vm.generate_image("a cinematic photo of a red fox in snow")
print(ref)   # {"$artifact": "...", "content_type": "...", ...}
png_bytes = vm.store.load_bytes(ref["$artifact"])
from pathlib import Path
from abstractvision import VisionManager
from abstractvision.backends import MLXGenBackendConfig, MLXGenVisionBackend

# Download each model first with `abstractvision download ... --provider mlx-gen`
images = VisionManager(backend=MLXGenVisionBackend(
    config=MLXGenBackendConfig(model="AbstractFramework/flux.2-klein-9b-8bit")))
image = images.generate_image("a studio photo of a red toy race car",
                              width=768, height=512, steps=12, guidance_scale=1.0)

# Edits and image-to-video take the source image as bytes
edit = images.edit_image("turn it into a watercolor",
                          image=Path("subject.png").read_bytes())

video = VisionManager(backend=MLXGenVisionBackend(
    config=MLXGenBackendConfig(model="AbstractFramework/wan2.2-i2v-a14b-diffusers-8bit")))
clip = video.image_to_video(
    Path("first-frame.png").read_bytes(),
    prompt="slow camera push-in",
    width=432, height=240, num_frames=41, fps=10, steps=20,
    guidance_scale=3.5, guidance_2=3.5,
)
Path("clip.mp4").write_bytes(clip.data)   # no store: a GeneratedAsset
# pip install abstractcore abstractvision  (the plugin is discovered automatically)
# Defaults to OpenAI images with OPENAI_API_KEY; set OPENAI_BASE_URL for a compatible server,
# or ABSTRACTVISION_BACKEND=mlx-gen | diffusers | sdcpp to run locally.
from abstractcore import create_llm

llm = create_llm("openai", model="gpt-4o-mini")
png_bytes = llm.vision.t2i("a red square", width=512, height=512, steps=20)
models = llm.vision.list_provider_models(task="text_to_image")
